# zensical-quarto

Write a website in Quarto with executable R code, and publish it with
[Zensical](https://zensical.org).

A Quarto format extension, **`zensical-gfm`**, renders `.qmd` files to Markdown
that Zensical understands: Quarto callouts become admonitions, tabsets become
content tabs, math is rendered by MathJax, and cross-references, citations and
footnotes all work.

```
example/*.qmd ──quarto render──▶ example/docs/*.md ──zensical build──▶ example/site/
               (runs your R code)                    (makes the website)
```

Two tools, two steps: **Quarto** runs the R code and writes Markdown,
**Zensical** turns that Markdown into the website.

## 1. Install (once)

| What | Why | How |
|---|---|---|
| [Quarto](https://quarto.org/docs/get-started/) ≥ 1.5 | renders `.qmd` | installer from quarto.org (tested with 1.10.18) |
| R with packages | runs the code chunks | `install.packages(c("knitr", "rmarkdown", "ggplot2", "dplyr", "tibble"))` |
| [uv](https://docs.astral.sh/uv/) | installs Zensical (a Python tool) | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |

Then, in this folder:

```bash
uv sync
```

This installs Zensical and the test tools into `.venv/`. You never have to
write Python; uv just provides the `zensical` command.

## 2. Build the example site

```bash
make site
```

This runs `quarto render example` and then `zensical build` in `example/`.
Open `example/site/index.html`, or better, use the live preview:

```bash
make serve
```

Then open <http://localhost:8000>. Every time you save a `.qmd` file it is
re-rendered, and the browser reloads.

Without `make`, run the two steps yourself:

```bash
quarto render example                     # .qmd -> example/docs/*.md
cd example && uv run zensical build      # docs/ -> site/
cd example && uv run zensical serve      # or: live preview on :8000
```

## 3. Write your own pages

Everything happens in `example/` (or a copy of it; see below):

```
example/
├── _quarto.yml        Quarto project config (format, output-dir: docs, freeze)
├── zensical.toml      website config: title, navigation, theme, extensions
├── index.qmd          ← your pages: plain Quarto with ```{r} chunks
├── analysis.qmd
├── ...
├── references.bib     bibliography for citations
├── javascripts/       MathJax config
├── _extensions ──▶    symlink to the format extension in ../_extensions
├── docs/              GENERATED by Quarto (don't edit)
├── site/              GENERATED by Zensical (don't edit)
└── _freeze/           cached R results (commit this)
```

To add a page:

1. Create `example/my-page.qmd`:

   ````markdown
   ---
   title: My page
   description: Shown in search results and the <meta> description.
   ---

   ::: {.callout-tip}
   Callouts, tabsets, math, @fig-x refs and [@citations] all work.
   :::

   ```{r}
   #| label: fig-x
   #| fig-cap: "A ggplot."
   ggplot2::ggplot(mtcars, ggplot2::aes(wt, mpg)) +
     ggplot2::geom_point()
   ```
   ````

2. Add it to the navigation in `example/zensical.toml`:

   ```toml
   nav = [
     { "Introduction" = "index.md" },
     { "My page" = "my-page.md" },   # note: .md, the rendered file
   ]
   ```

3. Run `make site` (or keep `make serve` running).

### Rendering from RStudio / Positron

The **Render** button works and writes `docs/<page>.md`, but its preview only
shows that raw Markdown, not the website. For the real site, keep
`make serve` (or `uv run zensical serve` in `example/`) running in a terminal.
After each Render, the site preview reloads with your changes.

### Starting your own project

1. Copy the `example/` folder somewhere.
2. Install the extension into it: `quarto add <github-user>/zensical-quarto`,
   or copy `_extensions/zensical/` into `<your-project>/_extensions/`. Do this
   instead of the symlink, which only works inside this repository.
3. Edit `zensical.toml` (`site_name`, `site_url`, `nav`) and write your pages.

Keep these settings in `zensical.toml`:

- The listed `markdown_extensions`. The output relies on
  `pymdownx.blocks.*`, `pymdownx.arithmatex`, `md_in_html` and the others, and
  listing extensions replaces Zensical's defaults.
- `site_url`. Without it Zensical turns off instant page navigation.

## Feature mapping

| Quarto feature | Becomes | Status |
|---|---|---|
| Callouts (note, tip, warning, caution, important), with/without title | `/// admonition \| Title` + `type:` | ✅ supported |
| Collapsible callouts (`collapse="true"/"false"`) | `/// details` (+ `open: true`) | ✅ supported |
| Nested callouts, callouts inside tabs | nested blocks with longer outer fences | ✅ supported |
| Callout ids (`{#nte-x .callout-note}`) | kept as the admonition's `id` (linkable) | ✅ supported |
| Tabsets (`.panel-tabset`) | `/// tab` (`new: true` starts each set) | ✅ supported |
| Inline/display math | `$…$`, `$$…$$` → arithmatex + MathJax 3 | ✅ supported |
| Figures (ggplot2, base plots) and tables (`knitr::kable`) with `#fig-`/`#tbl-` labels, `@fig-x` refs | `<figure id=… markdown>` + `<figcaption>`, Quarto's numbering | ✅ supported |
| Citations + bibliography | resolved during render | ✅ supported |
| Footnotes (`[^n]` and inline `^[…]`) | `footnotes` extension | ✅ supported |
| R chunks with output, `echo`/`output`/`warning`/`include` | highlighted ```` ```r ```` fences, output as ```` ```text ```` | ✅ supported |
| Front matter `title`, `description` | preserved YAML → `<title>`, `<meta name="description">` | ✅ supported |
| Code folding (`code-fold`) | `<details class="code-fold">` around the code | ✅ supported (unstyled) |
| Code annotations (`# <1>`) | markers removed, annotation list shown as plain text after the code | ⚠️ degraded |
| Margin content (`.column-margin`), column layouts (`.columns`) | plain `<div>`s, content in the main column | ⚠️ degraded |
| Chapter/section numbering (`number-sections`) | ignored | ⚠️ degraded |
| Callout cross-references (`@nte-x`) | the reference shows as **?@nte-x** (Quarto warns) | ❌ unsupported (xfail test) |
| htmlwidgets (plotly, leaflet, DT, …) | no Markdown representation | ❌ out of scope: use static ggplot2 figures |

## Limitations

- **Format name is `zensical-gfm`, not `zensical-md`.** Quarto's `md` base maps to
  pandoc's `markdown_strict` writer, which drops figure/table captions and ids.
- The Markdown in `docs/` is meant for Zensical (Python-Markdown + pymdownx) and
  isn't portable GitHub Markdown: it contains `///` blocks and `markdown="1"` HTML.
- Code annotations, margin/column layouts and section numbering degrade
  gracefully. Nothing errors, and the content stays readable.
- Callout cross-references (`@nte-x`) don't resolve: the callout filter has to run
  before Quarto's crossref pass. Link to the callout's id instead:
  `[see this note](#nte-x)`.
- `preserve-yaml` copies the entire front matter into `docs/`, including keys
  like `format:`. Zensical ignores keys it doesn't know.
- Citations are run by the format's own filter (`citeproc: false` +
  `citations.lua`), so don't set `citeproc: true` in a document.

## Freeze and CI

`execute: freeze: auto` stores R results in `example/_freeze/`. A page's code is
re-run only when that page's source changes. **Commit `_freeze/`.** CI then
rebuilds the site without re-running your analyses. Delete `_freeze/` (or one
page's folder in it) to force a re-run.

`.github/workflows/site.yml` installs Quarto, R, uv and the dependencies, then
runs `make site` and the tests. Run the workflow manually with
**deploy = true** to publish `example/site` to GitHub Pages.

## Tests

```bash
make test        # = uv run pytest
```

`tests/check_site.py` copies `tests/fixtures/` (one `.qmd` per feature) to
`tests/_build/`, renders it, builds it with the example's `zensical.toml`, and
checks the HTML. It also builds the example. If Playwright's Chromium is
installed (`uv run playwright install chromium`), it checks in a real browser that
instant navigation works and MathJax renders. That check needs network access;
otherwise it is skipped.

## How it works

`_extensions/zensical/` contains the format (`_extension.yml`) and one Lua filter
per concern, each documented at the top of its file: `callouts.lua`,
`tabsets.lua`, `blocks.lua` (writes the `///` fences), `math.lua`,
`figures.lua`, `code.lua`, `citations.lua`, `divs.lua`. `NOTES.md` records
the Quarto/Zensical behaviour these rely on, all verified on Quarto 1.10.18 and
Zensical 0.0.73.
